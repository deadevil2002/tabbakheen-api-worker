# Native order-tracking Worker handoff (Draft PR #13)

This source implements the Mobile PR #13 contract at `d983f507b8618d8aaad9143351d18b29cd74caa9` in `artifacts/mobile/NATIVE_ORDER_TRACKING_RELEASE_HANDOFF.md`. It is local/Draft code, not deployed. Existing Expo notifications, inbox, badges, and 1.0.6 APIs are unchanged. V2 order creation and irreversible account deletion remain OFF.

## API and storage

- `GET /order-tracking/capabilities` and `POST /order-tracking/register` require a verified Firebase ID token. `POST /order-tracking/rotate` and `/end` require the scoped `OrderTrackingLease` secret. Responses are JSON; capabilities report both remote platforms false unless the complete server configuration is present and both exact-string activation flags are `"true"`.
- Register checks customer ownership, active user status, order state, both deletion records, and a three-session order cap in one Firestore read-write transaction. It returns a <=8-hour HMAC lease, with only its SHA-256 hash indexed in Firestore. Rotation/end are CAS/idempotent; new/changed registrations and rotations are rate limited. Tracking session, registry, lease index, rate and event-job collections are Worker-private and must remain denied to direct clients under active Rules.
- Existing committed order transitions atomically add a small tracking job only while both remote gates are enabled. Cron processes one bounded projection, send or expiry-cleanup unit in its existing fast lane; one slot per six minutes reserves expiry cleanup even under backlog. It reads the authoritative order and at most three registered sessions; it never scans drivers, users or orders. A send is claimed durably before transport. Explicit 429 retries are capped; ambiguous transport outcomes remain `uncertain`, not blindly resent. Later authoritative states supersede older states. Accepted terminal updates revoke the lease/token; revoked sessions no longer match expiry queries.
- Native content state is an allowlist of stage, versions and time fields only. No destination, coordinates, contact, payment, or Expo token enters the native payload. Firestore Rules do not redact Worker-stored fields; direct-client access to these new private collections must be denied before activation.

## Owner/developer provisioning and activation gates

The human developer must verify the iOS bundle identifier `com.tabbakheen.app`, ActivityKit/Live Activity entitlement, Activity push-token handling, APNs topic `com.tabbakheen.app.push-type.liveactivity`, and Android FCM v1 native data-only receiver/notification permission in signed TestFlight and Play Internal Testing builds. The Worker needs owner-provisioned APNs team ID, key ID, p8 signing key and correct `production`/`development` APNs environment; the existing Firebase service account must have authorized FCM HTTP v1 send access for `tabbakheen-99883`. No key is in Git.

New Worker binding names (values are **not** committed): `ORDER_TRACKING_APNS_TEAM_ID`, `ORDER_TRACKING_APNS_KEY_ID`, `ORDER_TRACKING_APNS_PRIVATE_KEY_P8`, `ORDER_TRACKING_APNS_ENV`, `ORDER_TRACKING_LEASE_SECRET` (random >=32-character server secret), `ORDER_TRACKING_IOS_REMOTE_ENABLED`, `ORDER_TRACKING_ANDROID_REMOTE_ENABLED`. Both flags are absent/OFF by default. Do not enable either until credentials, active Rules' default denial of all tracking collections, native test builds, controlled transport tests and owner approval are verified. Mobile requires both capabilities true before remote tracking; V2 order creation requires its separate approval and remains OFF.

Local synthetic tests cover auth, registration/rotation/end, deletion races, APNs/FCM payloads, privacy, lost responses and commit reconciliation, and a 10,000-driver population; they do **not** prove Apple/Google credential acceptance, native display, real-device QA, production queue throughput or a full combined-Cron resource bound. Before activation, use approved isolated test recipients and verify APNs/FCM credentials, native display/end behavior, delivery latency, queue health and the 1.0.6 paths. Do not transmit a real push or enable the feature as part of this source handoff.
